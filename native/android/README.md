# Ely native Android profile

A runnable Android application renders the Go-owned profile JSON as Jetpack
Compose controls. There is no WebView. The small `protocol` JVM module owns
bounded decoding, action encoding, session-cookie HTTP transport, and the
revision-aware draft reducer. `app` owns actual native controls and lifecycle.

## Run

Requirements: Java 21, Android SDK platform 35, build-tools 35.0.0, and an Android
emulator/device with API 26 or newer. Android Studio can open this directory as a
Gradle project. Install/accept SDK components yourself when your environment does
not already provide them.

Start the Go demo from the repository root:

```sh
go run ./examples/native-sdui
```

Then, from this directory:

```sh
./gradlew :app:installDebug
adb shell am start -n dev.ely.nativeprofile/.MainActivity
```

The debug app uses `http://10.0.2.2:8094/native/profile`, Android Emulator's bridge
to the host loopback. The Go server must run on the emulator's host computer.
For a physical device, change the debug-only `PROFILE_ENDPOINT` to
`http://127.0.0.1:8094/native/profile` and run `adb reverse tcp:8094 tcp:8094`.
Endpoints are application configuration, never server-supplied tree properties.

Cleartext is allowed only for the three loopback/demo hosts in the debug source
set's network security configuration. Release uses an intentionally non-runnable
HTTPS placeholder until its host configures a real HTTPS endpoint. Release does
not inherit the debug cleartext policy. This demo has no production login.

## Checks

The wrapper pins Gradle 8.11.1 and its distribution SHA-256. With an already
configured Android SDK, run the same checks used by CI:

```sh
./gradlew --no-daemon :protocol:test :app:assembleDebug :app:testDebugUnitTest :app:assembleDebugAndroidTest
```

The APK is `app/build/outputs/apk/debug/app-debug.apk`; the launcher activity is
`dev.ely.nativeprofile.MainActivity`. Native UI tests require a running emulator:

```sh
./gradlew :app:connectedDebugAndroidTest
```

For SDK-free protocol, state, shared-fixture, and loopback HTTP tests:

```sh
./gradlew --no-daemon -PprotocolOnly :protocol:test
```

To additionally exercise the actual running Go server (load, validation, save,
exact replay, cookie persistence, and retained newer drafts):

```sh
ELY_NATIVE_TEST_BASE_URL=http://127.0.0.1:8094 ./gradlew --no-daemon -PprotocolOnly :protocol:test
```

Fixtures are generated by the Go implementation in `../fixtures`. Tests cover
canonical values, edits during saves, validation, exact retries, conflicts,
stale responses, response bounds, unsupported controls, and session/CSRF wiring.
The instrumentation tests exercise actual editable native fields, disabled save
feedback, error clearing, and focus retention through a full-region replacement.

## State and limits

- The authoritative baseline, local draft, and per-field edit revision are
  separate. Input changes stay local, including IME composition. Save is disabled
  during composition; keyboard Done also checks that composition has ended.
- One mutation is pending at a time. Its exact serialized JSON, request ID,
  CSRF token, submitted values, and edit revisions are retained for Retry. Later
  typing remains editable and is never added to that retry.
- Successful replies merge canonical values only when local edit revisions still
  match. Invalid/conflict replies preserve drafts. Newer edits clear stale errors.
- Request/session/screen IDs and versions gate response acceptance. The app
  releases loading feedback when a completed current call is ignored, while a
  completion belonging to a superseded call cannot alter the current request.
- A `CookieManager` retains HttpOnly demo session cookies for the ViewModel's
  lifetime, including activity configuration changes. Cookies and drafts are
  intentionally not persisted across process death; startup loads a fresh screen.
  No cookie or CSRF value is logged. The demo is not durable authentication.
- Stable node keys and retained `TextFieldValue` preserve focus, selection and IME
  composition through the profile region replacement. Values are never reloaded
  just because the server replaced the input's `value` property.
- The parser checks 1 MiB, 1,000 nodes, depth 32, unique IDs, required types and
  capabilities, typed supported properties, revision range through 2^53−1, one
  profile form/input and its registered submit action before rendering anything.
  Unknown optional members are ignored. Unsupported responses keep the last
  draft and display a native error with explicit reload/discard confirmation.
- Reload is never automatic. A user must acknowledge draft discard before
  replacing an existing screen. A save whose network result is unknown may
  already have succeeded; the reload confirmation explains this.

This renderer intentionally implements only the profile v1 protocol documented
in `../PROTOCOL.md`, including text inputs and form-submit buttons. It does not
interpret HTML, scripts, expressions, asset URLs, bindings, or arbitrary actions.
